# FoldKey

갤럭시 Z 폴드7 내부 화면에서 Python, 셸, vim, Go, 터미널 작업을 하기 위한 Android 키보드(IME, Input Method Editor)다. 한글 두벌식 입력을 지원한다. 배열과 기능을 정한 근거는 [docs/research.md](docs/research.md)에 있다.

## 빌드와 설치

필요한 것: JDK(Java Development Kit) 17 이상(Robolectric 테스트는 JDK 21), Android SDK(Software Development Kit) Platform 36, Build-Tools 36.0.0.

```sh
cd keyboard
echo "sdk.dir=$ANDROID_HOME" > local.properties
./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

설치 후 앱 목록의 FoldKey를 열고 다음 순서로 켠다.

1. "시스템 설정에서 FoldKey 사용 켜기"를 눌러 FoldKey를 켠다.
2. "입력 방법을 FoldKey로 선택"을 눌러 FoldKey를 고른다.
3. 같은 화면의 입력창과 "키 이벤트 확인창"에서 동작을 확인한다. 확인창은 터미널처럼 `TYPE_NULL` 입력을 요청하고, 받은 글자와 키 이벤트를 그대로 보여 준다.

adb(Android Debug Bridge)로 켜려면 다음 명령을 쓴다.

```sh
adb shell ime enable io.github.patissiermongs.foldkey/.ime.FoldKeyService
adb shell ime set io.github.patissiermongs.foldkey/.ime.FoldKeyService
```

## 배열

FoldKey에는 레이어가 둘 있다. 코드 레이어는 아래 표의 PC(personal computer) 배열이고, 일반 레이어는 메신저·검색·메모처럼 일상 글을 칠 때 쓰는 휴대폰식 배열이다([일반 레이어](#일반-레이어)). 두 레이어는 상단 줄의 `일반`/`코드` 버튼으로 바꾼다(0.10.0. 0.9.0까지는 배열 안의 키였다).

| 화면 | 기본 배열 | 키 간격(폴드7) |
|---|---|---|
| 내부 화면 세로(책 자세, 135.8 mm) | 전체 배열: ANSI(American National Standards Institute) 15칸 | 9.0 mm |
| 내부 화면 가로(150.7 mm) | 분할 배열 | 8.5 mm |
| 폭 110 mm 미만(커버 화면 65 mm) | 10열 compact 배열 | 6.4 mm |

- 세로와 가로의 전체/분할 선택은 따로 저장된다. 설정의 "세로 화면에서 분할 배열", "가로 화면에서 분할 배열"로 바꾼다. 0.10.0에서 상단 줄의 "분할"/"전체" 버튼은 뺐다.
- 분할 배열의 경계는 6|7, T|Y, G|H, V|B다(0.10.0. 0.5.0부터 0.9.0까지는 B|N). 두벌식 자음은 모두 왼쪽, 모음은 모두 오른쪽에 온다. 일반 레이어와 같은 글자 경계다. 두 반쪽 사이 안쪽 가장자리에는 보이지 않는 복제 키(T 옆 Y, Y 옆 T 등)가 있다.
- 분할 배열의 두 반쪽은 ANSI·HHKB(Happy Hacking Keyboard)처럼 줄마다 어긋난다. 0.10.0에서 바깥 끝 특수키를 줄여 `1`, `q`, `a`, `z`는 왼쪽 끝에서 0.75, 1, 1.25, 1.75칸에 있다(0.9.0까지 1, 1.5, 1.75, 2.25칸). 두 반쪽 사이 간격은 모든 줄에서 같아 계단 모양이 된다.
- 0.10.0에서 쓰임에 비해 자리를 많이 차지하던 키를 줄였다. 기호 키 `` ` `` `[` `]` `\` `;` `'` `,` `.` `/`는 0.75칸, Tab은 1칸, Esc/Ctrl은 1.25칸, 왼쪽 Shift는 1.75칸, ⏎와 오른쪽 Shift는 1.25칸이다. ⌫는 HHKB처럼 `]` 오른쪽(⏎ 위)에 1칸으로 있고, `\`는 숫자 행 `=` 오른쪽에 있다. 글자·숫자와 `-` `=`는 1칸 그대로다. 근거와 측정은 [docs/research.md](docs/research.md) 3.14절에 있다.
- 배열 폭은 14.5칸에서 13.5칸, 왼쪽 반쪽은 7.25칸에서 6.75칸, 오른쪽 반쪽은 8칸에서 7.75칸이 된다. 오른쪽 바깥 끝은 줄마다 다르다. 숫자 행과 `q` 행이 가장 길고, ⏎ 행은 0.5칸, Shift 행은 1.25칸, 스페이스 행은 1칸 짧다. 줄마다 마지막 키의 판정 영역은 화면 끝까지 이어진다. 폴드7 세로 분할에도 키 너비 8.5 mm가 그대로 들어간다(0.9.0은 8.2 mm로 줄었다).
- 맨 아래 줄은 왼쪽이 Ctrl, Alt, Fn, `한/A`, 스페이스이고 오른쪽이 스페이스와 방향키다. `한/A`는 0.9.0의 `일반` 키 자리인 왼쪽 스페이스 바로 옆에 있고, 오른쪽 반쪽의 `한/A`는 뺐다.
- 키 너비 7.0 mm의 가로 분할에서 두 반쪽은 화면 옆 끝에서 47.8 mm, 54.8 mm까지 온다(0.9.0은 51.3 mm, 56.5 mm, 0.4.1은 47.8 mm, 63.5 mm). 근거와 비교한 다른 안은 [docs/research.md](docs/research.md) 3.9절과 3.14절에 있다.
- 분할 배열 가운데의 빈 공간에서 줄마다 12 mm 이상 남으면 그 자리에 복사한 글 기록을 보여 준다([분할 배열 가운데](#분할-배열-가운데)). 폴드7 가로 화면(키 너비 8.5 mm)에서는 간격이 35.0 mm라 한 칸 폭 복제 키 둘을 빼고도 위 네 줄에 18.0 mm가 남는다(0.9.0은 간격 26.5 mm에서 복제 키를 반 칸으로 줄여 18.0 mm를 만들었다). 세로 분할은 간격 20.1 mm에서 반 칸 복제 키 둘을 빼면 11.6 mm라 표시하지 않는다.
- 숫자 행은 항상 보인다. 기호 키는 PC(personal computer) 키보드와 같은 자리에 있다.

## 입력 방법

| 동작 | 결과 |
|---|---|
| 키를 위로 밀기 | Shift 글자(`9` → `(`, `'` → `"`, `-` → `_`, `4` → `$`, `\` → `\|`, 글자는 대문자, 한글은 쌍자음·ㅒ·ㅖ) |
| 키를 아래로 밀기 | Ctrl(control)+키(`c` → `^C`, `[` → Esc와 같은 `^[`). 숫자 행과 `-` `=`은 F1–F12 |
| 길게 누르기(기본 400 ms) | 위로 밀기와 같음. 설정에서 반복 입력으로 바꾸면 vim의 `j`처럼 누르고 있는 동안 반복 |
| 스페이스에서 끌기 | 좌우는 커서 이동(2.5 mm마다 한 칸), 위아래는 ↑/↓(4 mm마다 한 줄). 처음 움직인 방향으로 고정된다. Shift를 켜고 끌면 선택 |
| 스페이스를 꾹 누른 뒤 끌기 | 선택(Shift+방향키). 길게 누르기 시간(기본 400 ms)이 지나면 스페이스 키 색이 바뀐다. 처음 움직인 방향으로 고정된다. 움직이지 않고 떼면 아무것도 입력하지 않는다. 터미널에서는 Shift 없이 커서만 움직인다 |
| Esc/Ctrl 키(Caps Lock 자리) | 짧게 누르면 Esc(escape), 누른 채 다른 키를 치면 Ctrl. 누르고 0.15초 안에 다음 키를 눌러 Esc/Ctrl을 먼저 떼면 Esc 다음에 그 키가 나가고, 그보다 늦게 누른 키는 Esc/Ctrl을 먼저 떼도 Ctrl 조합이다. Fn을 켜고 누르면 Insert(Shift도 켜면 Shift+Insert) |
| Shift, Ctrl | 한 번 누르면 다음 키 한 번에 적용, 350 ms 안에 두 번 누르면 고정, 누른 채 치면 조합. 누른 채 친 키는 수정키를 먼저 떼도 조합으로 들어간다. 고정한 Shift는 영문 글자와 함께 숫자·기호에도 적용된다(0.10.0. `1` → `!`, `/` → `?`). 한글 자모(쌍자음)와 Ctrl·Alt 조합에는 고정한 Shift를 더하지 않는다 |
| Alt(alternate) | 누를 때마다 켜고 끈다(0.10.0. Fn과 같은 전환 방식). 켜져 있는 동안 치는 키는 모두 Alt 조합이고 Alt 키와 상단 줄에 켜진 상태가 보인다. 누른 채 쳐도 조합이다 |
| Fn(function) | 누를 때마다 숫자판을 켜고 끈다. 누른 채 치면 손을 뗄 때 꺼진다([숫자판](#숫자판fn)) |
| 방향키 위로 밀기 | Home, PgDn, PgUp, End |
| 방향키·`⌫` 누르고 있기 | 반복 입력. 첫 입력에 붙은 one-shot 수정키가 반복 내내 붙고, 다른 키를 누르면 반복이 멈춘다 |
| `한/A` | 짧게 누르면 FoldKey의 한글·영문 전환. 길게 누르면(길게 누르기 시간, 0이면 400 ms) 오른쪽 Alt 키 이벤트(`KEYCODE_ALT_RIGHT`)를 수정키 없이 누르고 뗀다(0.10.0). 원격 데스크톱 너머의 Windows가 오른쪽 Alt를 한/영 키로 쓰는 한국어 키보드 종류(아래 설명)이면 원격 PC의 한글·영문이 바뀐다. FoldKey 자신의 한글·영문 상태와 켜 둔 수정키는 그대로이고, 누르고 있는 동안 팝업에 `한/영`이 나온다 |
| 상단 줄 `일반`/`코드` | 코드 레이어와 일반 레이어 전환. 코드 레이어에서는 `일반`, 일반 레이어에서는 `코드`라고 표시된다 |

밀기 동작은 손을 떼기 전에 결과(`^C`, `F5`, `(` 등)를 팝업으로 보여 준다. 손가락을 처음 자리로 되돌리면 일반 탭이 된다.

상단 줄에는 현재 언어, 켜진 수정키, 조합 중인 한글(터미널에서), 최근에 보낸 특수키(`Esc`, `^C`, `M-b`(Alt+b), `Tab`, `⏎`, 방향키, `한/영`)와 모두 선택·복사·잘라내기·붙여넣기·`일반`/`코드`·설정·숨김·`띄우기`/`고정` 버튼이 있다. 키보드를 띄운 동안에는 불투명도 슬라이더와 `접기` 버튼이 더 나온다([띄운 키보드](#띄운-키보드)). 0.10.0에서 분할/전체 버튼과 키보드 전환 버튼을 빼고 잘라내기와 레이어 전환을 넣었다. 다른 키보드로 바꿀 때는 FoldKey 설정 화면의 "입력 방법을 FoldKey로 선택"(시스템 입력 방법 선택 창)이나 시스템 내비게이션의 키보드 버튼을 쓴다. 모두 선택, 복사, 잘라내기, 붙여넣기는 입력창이 가진 같은 동작(`performContextMenuAction`)을 부른다. 그래서 비밀번호 입력창처럼 앱이 복사를 막은 곳에서는 복사되지 않는다. 터미널 입력창에서는 모두 선택·복사·잘라내기를 숨기고, 붙여넣기는 클립 글자를 그대로 보낸다.

`한/A` 길게 누르기가 원격 PC에서 하는 일은 그 PC의 한국어 키보드 종류가 정한다. Windows의 한국어 키보드 드라이버 네 가지 가운데 101키 종류 1(`kbd101a`)은 오른쪽 Alt가 한/영, 오른쪽 Ctrl이 한자이고, 종류 2(`kbd101b`)는 반대로 오른쪽 Ctrl이 한/영, 오른쪽 Alt가 한자다. 종류 3(`kbd101c`)은 Shift+Space가 한/영, Ctrl+Space가 한자이고, 103/106키(`kbd103`)는 전용 한/영·한자 키를 쓴다. 원격 PC에서 오른쪽 Alt가 한/영으로 동작하지 않으면 그 PC의 한국어 키보드를 종류 1로 바꾼다. FoldKey는 이 이벤트를 사용자가 Parsec에서 동작을 확인한 이전 키보드 앱과 같은 형태(`KeyEvent(t, t, action, KEYCODE_ALT_RIGHT, 0, 0)`, flags 0)로 보낸다.

## 숫자판(Fn)

Fn을 켜면 위 네 줄에서 `h` 키의 왼쪽 끝보다 오른쪽으로 걸친 키(분할 배열에서는 오른쪽 반쪽의 위 네 줄 전부)가 사라지고, 오른쪽 끝 다섯 칸에 곧은 숫자판이 나온다. 맨 아래 줄(스페이스, 한/A, 방향키)과 왼쪽 부분은 그대로다. 숫자판과 왼쪽 부분 사이는 비어 있고, 눌러도 입력되지 않는다.

```
7  8  9  /  ⌫
4  5  6  *  (
1  2  3  -  )
0  .  =  +  ⏎
```

숫자판의 ⌫를 위로 밀면 Del(forward delete)이다.

- 키 폭은 글자 키와 같다(폴드7 세로 분할 8.5 mm, 커버 화면 6.4 mm). `7 4 1 0` 열의 중심은 폴드7 세로 분할에서 오른쪽 끝으로부터 38.8 mm다.
- 커버 화면에서는 오른쪽 반쪽이 숫자판이 된다.
- Fn은 누를 때마다 숫자판을 켜고 끈다. 누른 채 치면 손을 뗄 때 꺼진다. 숫자판이 켜져 있는 동안 Esc 자리는 Insert다.
- 숫자판 키는 Shift·Ctrl·Alt와 상관없이 표시된 글자를 입력한다. 밀기와 길게 누르기 동작은 없다. ⌫는 누르고 있으면 반복한다.
- 숫자판을 누른 위치는 터치 편차 학습에 쓰지 않는다.
- 0.3.0까지 Fn에 있던 특수문자 53개와 다른 키와 겹치던 Fn 조합(Fn + 숫자의 F1–F12, Fn + 방향키, Fn + h j k l 등)은 뺐다. F1–F12는 숫자 행 아래로 밀기, Home·End·PgUp·PgDn은 방향키 위로 밀기로 입력한다. Fn + Esc(Insert)는 남겼다.
- 커버 화면 배열에는 방향키가 없다. 0.3.0까지 커버 화면의 방향키였던 Fn + h j k l(Fn + y o, u i는 Home·End·PgDn·PgUp)은 숫자판과 자리가 겹쳐 뺐다. 커버 화면에서는 스페이스를 끌어 커서를 옮긴다.

## 일반 레이어

상단 줄의 `일반` 버튼을 누르면 휴대폰 키보드와 같은 QWERTY(윗줄 왼쪽 여섯 글자로 부르는 영문 배열)로 바뀐다. `코드` 버튼을 누르면 돌아온다. 아래는 전체 배열(분할하지 않은 화면)이다.

```
1 2 3 4 5 6 7 8 9 0
q w e r t y u i o p
 a s d f g h j k l
⇧  z x c v b n m  ⌫
한/A  스페이스  , . ⏎
```

분할 배열은 0.10.0부터 ANSI처럼 줄마다 어긋난다. 왼쪽 반쪽에서 `q`는 `1`보다 0.5칸, `a`는 0.75칸 오른쪽에서 시작하고, `z`는 1.25칸 ⇧ 다음에 온다. 오른쪽 반쪽도 같은 어긋남이라 `y`는 `6`보다 0.5칸, `h`는 0.75칸, `b`는 0.25칸 오른쪽이다. 0.9.0까지는 휴대폰처럼 `a` 줄만 반 칸 들여 놓았다.

```
1 2 3 4 5        6 7 8 9 0
 q w e r t        y u i o p
  a s d f g        h j k l
⇧  z x c v       b n m  ⌫
한/A 스페이스     스페이스 , . ⏎
```

- 숫자 행을 위로 밀면 PC와 같은 Shift 기호(`! @ # $ % ^ & * ( )`), 아래로 밀면 `1`부터 `~ - _ = + ; : ' " /`가 나온다. 아래로 미는 기호는 키 왼쪽 아래에 작게 표시된다.
- `,`를 위로 밀면 `!`, `.`를 위로 밀면 `?`다. Shift를 켜고 눌러도 같다. 아래로 밀면 `,`와 `.` 그대로다.
- 윗줄 글자를 아래로 밀면 코드에 쓰는 기호가 나온다(0.10.0): `q` → `` ` ``, `w` → `\`, `e` → `|`, `t` → `[`, `y` → `]`, `u` → `<`, `i` → `>`, `o` → `{`, `p` → `}`. 기호는 키 왼쪽 아래에 작게 표시되고, 한글 모드의 영문 글자 표시는 오른쪽 아래에 그대로 있다. `r`은 다른 글자 키처럼 Ctrl+R이다. 마크다운의 코드 블록과 링크, Python의 리스트·딕셔너리, HTML(HyperText Markup Language) 태그에 쓰는 기호 가운데 일반 레이어에 없던 아홉 개다.
- 글자 키는 코드 레이어와 같다. 위로 밀면 대문자·쌍자음, 아래로 밀면 Ctrl+글자(일반 입력창의 Ctrl+A/C/V/Z, 윗줄은 위의 기호), 한글 키에는 영문 글자가 함께 표시된다.
- Esc/Ctrl, Ctrl, Alt, Fn, Tab, 방향키, F1–F12, 숫자판은 없다. 커서 이동과 선택은 스페이스 끌기로 한다.
- 분할 배열의 경계는 5|6, T|Y, G|H, V|B다. 두벌식 자음은 모두 왼쪽, 모음은 모두 오른쪽에 온다. 안쪽 가장자리에는 코드 레이어처럼 복제 키가 있다.
- 0.7.1부터 분할 배열의 두 반쪽은 기본으로 화면 옆 끝에서 14 mm 떨어져 놓인다. 0.7.0에서는 옆 끝에 붙어 있었다. 0.8.0부터 왼쪽과 오른쪽 거리를 따로 정하고(설정 "일반 레이어 분할 배열", 0–40 mm), 엄지 범위 측정이 두 값을 정한다([반쪽 높이와 크기](#반쪽-높이와-크기)). 0.7.1에서 바꿔 둔 거리는 두 값의 시작값이 된다. 반쪽과 옆 끝 사이를 누르면 가장 가까운 바깥 키가 입력된다.
- 분할 배열의 키 너비가 "자동"이면 코드 레이어 키 너비에서 정한다. 코드 레이어 키 너비보다 좁아지지 않고, 9.6 mm까지는 옆 끝에서 띄운 거리까지 더해 두 반쪽이 코드 레이어의 같은 쪽 반쪽보다 멀리 가지 않는 한도에서 커진다. 엄지 범위 측정은 이 값을 직접 정한다(4.0–11.0 mm). 아래 수치는 자동일 때다.
  - 0.10.0에서 일반 레이어 반쪽은 어긋남 때문에 왼쪽 5.75칸, 오른쪽 5.5칸으로 넓어지고(0.9.0은 5.5칸·5칸) 코드 레이어 반쪽은 좁아졌다. 그래서 기본 옆 거리 14 mm에서는 커질 여지가 없어 코드 레이어와 같은 키 너비가 되고, 왼쪽 반쪽은 코드 레이어보다 안쪽까지 온다.
  - 폴드7 가로 화면, 키 너비 7.0 mm 설정에서는 7.0 mm 키다. 두 반쪽은 옆 끝에서 14.0–54.3 mm와 14.0–52.5 mm에 놓인다(0.9.0은 14.0–52.5 mm와 14.0–49.0 mm).
  - 기본값 8.5 mm에서는 8.5 mm 키로, 14.0–62.9 mm와 14.0–60.8 mm다(0.9.0은 8.75 mm 키, 14.0–62.1 mm와 14.0–57.8 mm).
  - 같은 화면과 설정에서 코드 레이어는 옆 끝부터 47.8 mm·54.8 mm, 57.9 mm·66.4 mm까지다.
- 0.8.0부터 옆 끝 거리를 먼저 지키고, 두 반쪽과 복제 키가 화면에 들어가지 않으면 키가 줄어든다. 0.7.1은 반대로 거리부터 줄였다. 가운데 패널은 남은 간격이 있을 때만 나와서, 세로 분할에서 키 너비 8.5 mm이면 나오지 않는다.
- 코드 레이어의 기본 옆 끝 거리는 0.5 mm다. 벽 쪽 열이 `` ` ``, Tab, Esc/Ctrl, ⇧, Ctrl과 `\`, ⌫, ⏎, ⇧, 방향키라서 글자 키는 이미 벽에서 떨어져 있다. 0.8.0부터 코드 레이어도 왼쪽·오른쪽 거리를 따로 바꾸고, 엄지 범위 측정이 함께 정한다.
- 전체 배열과 커버 화면에서는 10칸 배열이 가운데에 놓인다. 폴드7 세로 화면의 키 너비는 11.5 mm, 커버 화면은 6.4 mm다. 커버 화면에서는 코드 레이어보다 한 줄 낮다.
- 터미널 입력창은 늘 코드 레이어로 열린다. 다른 입력창은 터미널이 아닌 곳에서 마지막으로 고른 레이어로 열리고, 이 선택은 키보드를 다시 켜도 남는다. 터미널에서 바꾼 레이어는 그 입력창에만 적용된다. 한글·영문 선택과 같은 방식이지만, 비밀번호·URL(Uniform Resource Locator)·이메일·숫자 입력창은 영문으로 시작해도 레이어는 마지막 선택을 따른다.
- 레이어를 바꾸면 조합 중인 한글을 먼저 보내고, 켜 둔 Shift·Ctrl·Alt·Fn은 꺼진다.
- 터치 편차 학습값은 레이어마다 따로 쌓는다.
- 근거와 측정값은 [docs/research.md](docs/research.md) 3.10절(레이어)과 3.11절(옆 끝에서 띄우기)에 있다.

## 분할 배열 가운데

가로 분할 배열에서 두 반쪽 사이의 위 네 줄을 줄마다 위아래 두 칸으로 나눠, 모두 여덟 칸에 복사한 글 기록을 보여 준다(0.10.0. 0.9.0까지는 위 두 줄이 기록, 아래 세 줄이 입력 내용 표시였다). 칸은 두 반쪽이 끝나는 자리를 따라 줄마다 폭과 위치가 달라 계단 모양이다. 엄지에서 가장 먼 자리라서 자주 누르는 키는 두지 않는다. 스페이스 줄은 스페이스를 치다가 클립을 잘못 누르지 않게 비워 둔다.

- 칸을 누르면 그 글을 붙여 넣고, 위아래로 끌면 다음 기록으로 넘어간다. 기록이 여덟 칸보다 많으면 오른쪽에 위치 막대가 보인다. 여러 줄이면 미리보기에 ⏎가 보인다. 칸 높이는 행 높이의 절반(기본 9.5 mm에서 4.75 mm)이다.
- 기록을 길게 누르면 그 칸이 고정·삭제 두 버튼으로 바뀐다. 다른 곳을 누르면 닫힌다.
  - 고정한 글은 📌와 함께 맨 위에 오고, 시간이 지나도 지워지지 않는다. 20개까지 고정할 수 있다. 고정을 풀면 일반 기록의 맨 위로 돌아간다.
  - 고정하지 않은 글은 기본 20개, 24시간까지 보관한다(설정에서 5–50개, 1–72시간). 복사한 시각(기기 시계)에서 보관 시간이 지나면 지운다.
  - 0.10.0부터 고정하지 않은 글도 기기에 저장해 키보드 프로세스가 끝나거나 기기를 다시 켜도 남는다. 고정한 글과 함께 앱 저장소의 백업 제외 영역(`noBackupFilesDir`)에 있는 파일 하나에 쓴다. 0.9.0이 저장한 고정 목록 파일은 그대로 읽는다. 기기를 다시 켠 뒤에는 처음 잠금을 풀어야 이 영역을 읽을 수 있다.
  - 설정의 "가운데에 복사한 글 표시"를 끄면 고정하지 않은 기록을 메모리와 파일에서 모두 지운다. 고정한 글은 남는다.
  - 지운 글이 시스템 클립보드의 현재 클립이면 시스템 클립보드도 비운다. 그러지 않으면 다음에 키보드를 띄울 때 같은 클립이 다시 기록된다.
- 비밀번호 관리 앱처럼 `ClipDescription`에 민감 표시(`android.content.extra.IS_SENSITIVE`)를 붙인 클립은 기록하지 않으므로 고정할 수도, 저장될 수도 없다.
- 기기가 잠겨 있는 동안(잠금 화면의 비밀번호 입력창 등)에는 기록을 보여 주지도 새로 기록하지도 않는다. Android도 잠긴 동안에는 시스템 클립보드를 어느 앱에도 넘기지 않는다.
- 0.10.0에서 가운데의 입력 내용 표시(커서 앞 글자, 터미널에서 친 글자)와 그 설정 두 개를 뺐다. 터미널에서 조합 중인 한글은 계속 상단 줄에 보인다.
- 터미널에서 여러 줄 클립을 붙이면 셸이 줄마다 실행할 수 있다. 붙이기 전에 미리보기의 ⏎를 확인한다.

## 반쪽 높이와 크기

- "분할 반쪽을 화면 아래 끝에서 띄우는 높이"(0–30 mm)를 올리면 반쪽 아래에 빈 공간이 생기고 키보드 높이가 그만큼 늘어난다. 맨 아래 행의 판정 영역은 그 빈 공간까지 넓어진다. 키보드 높이가 화면 높이의 60%를 넘으면 행 높이를 줄인다(0.7.x까지 50%).
- 분할 배열은 레이어마다 "키 너비", "화면 왼쪽 끝에서 띄우는 거리", "화면 오른쪽 끝에서 띄우는 거리"를 따로 둔다(거리 0–40 mm). 기본 거리는 코드 레이어 0.5 mm, 일반 레이어 14 mm다. 거리를 먼저 지키고, 두 반쪽과 복제 키가 화면에 들어가지 않으면 키가 줄어든다. 바깥 열 키의 판정 영역은 화면 끝까지 이어진다.
- "엄지 범위와 타이핑으로 분할 배열 맞추기"는 엄지 범위 측정 화면을 열고, 이어서 타이핑 보정 화면으로 넘어간다(0.9.0). 키보드를 사용 설정하고 입력 방법으로 고른 뒤 설정 앱을 처음 열 때 이 흐름이 한 번 자동으로 열린다.
- 엄지 범위 측정
  - 기기를 평소처럼 쥐고 엄지마다 편하게 닿는 곳을 문질러 칠하듯 그린다. 손을 뗄 때까지가 한 번이고, 엄지마다 세 번 한다.
  - 한 번 그린 획을 0.5 mm 칸으로 나눈다. 가로줄마다 옆 끝에서 가장 가까운 점과 먼 점, 세로줄마다 가장 낮은 점과 높은 점을 구하고, 각각의 중앙값을 그 획의 가까운 끝·먼 끝·아래 끝·위 끝으로 삼는다. 한 번 튀어 나간 선이 경계를 끌고 가지 않게 하려는 것이다. 폭 12 mm, 높이 15 mm보다 좁거나 칸이 16줄보다 적으면 다시 그리게 한다.
  - 세 번 그린 값이 네 경계 가운데 하나라도 6 mm와 중앙값의 10% 가운데 큰 값보다 많이 다르면 다시 그리게 하고, 일정하면 중앙값을 쓴다.
  - 잰 범위로는 시작 크기와 반쪽의 가운데 자리만 정한다. 시작 키 너비는 반쪽 칸 수(0.10.0의 코드 레이어 6.75칸·7.75칸, 일반 레이어 5.75칸·5.5칸)가 범위 폭에 들어가는 값이고(0.1 mm 단위 내림), 시작 행 높이는 다섯 줄이 범위 높이에 들어가는 값이다. 문질러 그린 범위가 실제로 칠 때보다 좁게 나온다는 사용자 보고가 있어, 반쪽을 범위 끝에 맞추지 않는다.
  - 두 엄지 모두 세 번이 일치하면 시작 크기로 맞춘 코드 또는 일반 레이어 배치를 범위 위에 겹친다. "미리보기" 버튼으로 레이어를 바꾸고, "다음: 타이핑 보정"으로 넘어간다.
- 타이핑 보정
  - 화면 위에 나온 글을 아래 키보드로 따라 친다. 코드 레이어는 셸·vim·Python·Go 줄, 일반 레이어는 한글·영문 문장이고, Shift 없이 치는 키만 쓴다. 친 부분은 흐려지고 다음 글자에 밑줄이 생긴다(한글은 음절을 다 쳐야 흐려진다). 그 아래 줄에 지금까지 친 글을 조합해 보여 준다. 다른 키가 눌리면 글이 넘어가지 않으므로 맞는 키를 다시 누른다.
  - 터치마다 노린 키 중심에서 벗어난 거리를 기록한다. 구역(줄 × 화면 4등분)마다 평균 편차를 구하고(표본이 적은 구역은 같은 엄지의 평균 쪽으로 당긴다), 그 편차를 뺀 뒤 남는 흩어짐의 표준편차를 엄지와 축마다 구한다. 구역 평균을 같은 탭으로 구한 만큼 자유도를 빼서 나누므로(잔차 유효 자유도), 구역마다 탭이 몇 개뿐이어도 표준편차를 작게 잡지 않는다. 엄지별 중앙값에서 중앙절대편차 기반 척도의 4배보다 멀리 떨어진 탭은 빼고 계산한다.
  - 키 너비는 가로 표준편차 × 2 × 1.96, 행 높이는 세로 표준편차 × 2 × 1.96이다. 편차를 보정한 뒤 터치의 95%가 가로로, 또 95%가 세로로 노린 키 안에 떨어지는 크기다(축마다 95%). 두 축이 모두 이 크기로 정해지면 키 안에 떨어지는 비율은 약 90%(0.95²)다. 두 엄지 가운데 큰 값을 쓰고, 그 회차의 크기보다 작게는 줄이지 않는다(키 4.0–11.0 mm, 행 5.0–15.0 mm). 흩어짐을 정해 둔 모의 입력(조건마다 200회)에서 키가 커진 조건의 키 너비는 필요한 값보다 중앙값으로 약 13% 컸고, 마지막 회차 적중률은 조건별 평균 95.7–96.7%였다([research.md 3.13절](docs/research.md#313-타이핑으로-키-크기와-보정값-맞추기090)).
  - 한 회차는 글자 60개다. 계산한 크기가 지금보다 5% 넘게 크면, 그 크기와 앞 회차에서 구한 보정으로 한 회차를 더 친다(레이어마다 최대 3회차).
  - 반쪽은 엄지 범위의 가운데에 반쪽 가운데를 맞춘다. 두 반쪽과 복제 키가 화면에 들어가지 않으면 키를 줄이기 전에 반쪽을 옆 끝 쪽으로 옮긴다. 행 높이는 두 레이어 가운데 큰 값을 함께 쓰고, 키보드 높이가 화면 높이의 60%를 넘지 않게 한다.
  - 결과 화면에 레이어마다 시작 → 최종 키 너비와 행 높이, 옆 거리, 회차별 적중률(다른 키가 눌리지 않은 탭의 비율), 엄지별 흩어짐을 적고 최종 배치를 엄지 범위 위에 그린다. "적용"을 누르면 크기와 자리, 구역별 보정값(학습한 터치 편차)을 저장하고, 실행 중인 키보드도 이 보정값을 바로 읽는다. 건너뛴 레이어는 그대로 둔다.
  - "타이핑만 다시 해서 맞추기"는 측정 없이 지금 설정의 크기와 반쪽 가운데에서 시작한다.
- 0.8.0은 엄지 범위만으로 크기를 정해 0.7.1 그림의 범위에서 코드 레이어 키가 4.3 mm가 되었고, 사용자가 이 크기에서 오타가 매우 심하다고 알렸다. 연속 입력 과제의 오류율은 7.7 mm 이상에서 유의한 차이가 없었다는 측정이 있다(Parhi 외 2006).
- 0.10.0에서 두 레이어의 반쪽 칸 수가 바뀌었으므로, 0.9.0에서 맞춘 옆 거리는 반쪽 가운데가 엄지 범위 가운데에서 조금 비켜 난다(코드 레이어 왼쪽은 0.25칸 바깥, 오른쪽은 0.125칸 바깥, 일반 레이어는 왼쪽 0.125칸·오른쪽 0.25칸 안쪽). 타이핑 보정을 다시 하거나 [터치 히트맵의 배치 제안](#오타를-줄이는-장치)으로 맞춘다.

## 터미널과 vim

- 입력창의 `inputType` class가 `TYPE_NULL`이면 터미널로 다룬다. Termux, ConnectBot, JuiceSSH, Android Terminal Emulator는 설정의 목록으로도 지정된다.
- 터미널에서는 조합 중인 한글을 앱에 보내지 않고 상단 줄에 표시한다. 음절이 완성되면 보낸다. Enter, 방향키, Esc, Ctrl 조합을 보내기 전에는 조합 중인 음절을 먼저 보낸다. 화면을 돌리거나 접어도 조합 중인 음절은 보낸 뒤 키보드를 다시 그린다.
- 터미널에서 수정키 없는 Enter와 Tab은 키 이벤트가 아니라 글자(`\n`, `\t`)로 보낸다. Android는 IME가 보낸 키 이벤트를 앱의 메시지 큐에 한 번 더 넣은 뒤 처리하고 글자는 바로 처리해서, 두 엄지로 겹쳐 누르면 뒤 글자가 Enter보다 먼저 도착할 수 있다. Termux는 `\n`을 Enter(CR, carriage return)로, `\t`를 Tab으로 받는다. 여러 줄 일반 입력창의 Enter도 `\n` 글자다.
- Ctrl과 Alt는 `META_CTRL_ON | META_CTRL_LEFT_ON`, `META_ALT_ON | META_ALT_LEFT_ON`을 붙인 키 이벤트로 보낸다. Termux의 Alt+글자(ESC(escape) 문자 접두어)와 일반 입력창의 Ctrl+A/C/V/X/Z가 이 방식으로 동작한다.
- Termux는 Ctrl+Alt 키 이벤트를 자체 단축키로 가져가므로, 터미널에서 Ctrl+Alt+글자는 ESC와 제어 문자를 이어 붙인 문자열로 보낸다. 제어 문자 대응은 Termux와 같다(Space·2·@ → NUL, 3 → ESC, 4 → FS, 5 → GS, 6 → RS, 7·/ → US, 8·? → DEL). Termux가 글자로 받으면 다른 문자로 바꾸는 NUL과 LF(line feed, Ctrl+J)는 ESC만 글자로 보내고 Ctrl+Space, Ctrl+J 키 이벤트를 잇는다.
- 한글 모드에서 Esc나 Ctrl+[를 보내면 영문 모드로 바뀐다(설정에서 끌 수 있음). vim에서 normal mode(일반 모드)로 돌아갈 때 한글로 명령이 들어가는 일을 막는다.
- Termux의 extra keys 줄은 FoldKey와 기능이 겹친다. 필요 없으면 `~/.termux/termux.properties`에 `extra-keys = []`를 넣고 `termux-reload-settings`를 실행한다.

## 띄운 키보드

상단 줄의 `띄우기`를 누르면 키보드가 같은 자리, 같은 크기 그대로 앱 화면 위에 뜬다(0.11.0). 앱은 키보드 높이만큼 줄어들거나 밀려 올라가지 않고 화면 전체를 쓴다. 원격 데스크톱처럼 화면 아래쪽까지 보고 눌러야 하는 앱을 위한 상태다.

- 떠 있는 동안 상단 줄 버튼 왼쪽에 불투명도 슬라이더가 나온다. 20–100%(5% 단위, 기본 70%)이고, 끄는 동안 바로 반영되며 손을 떼면 저장된다. 키보드 배경, 키, 글자가 같은 비율로 투명해진다. 설정 화면에는 이 항목이 없다.
- `접기`를 누르면 키보드가 사라지고 `접기` 버튼 자리에 ⌨ 손잡이(가로 11 mm 이상, 높이 6.5 mm)만 남는다. 손잡이 밖을 누르면 뒤의 앱이 그 터치를 받는다. 손잡이를 누르면 키보드가 같은 자리에 다시 나온다. 접고 펴는 동안 키보드 창의 크기는 그대로이고 터치를 받는 영역만 바뀌므로, 앱의 화면 배치는 다시 계산되지 않는다. 접을 때 조합 중인 한글은 확정한다.
- `고정`을 누르면 원래처럼 붙은 키보드로 돌아가고, 앱은 다시 키보드 위로 줄어든다. 띄운 상태는 저장되어 다음에 키보드가 나올 때도 이어진다. 접은 상태는 키보드 창이 닫히면 풀린다.
- 떠 있는 키보드는 앱의 입력창을 가릴 수 있다. 입력창이 화면 아래쪽에 있는 앱에서는 불투명도를 낮추거나 `고정`으로 돌아간다.
- 키보드 영역에서 시작한 화면 옆 끝 밀기는 뒤로 가기 제스처로 처리하지 않는다. 붙은 키보드에서 Android가 키보드 영역을 뒤로 가기 제스처에서 빼는 것과 같다.

## 물리 키보드

블루투스나 USB 키보드가 연결되어 있으면(시스템 구성의 `keyboard`가 `KEYBOARD_QWERTY`이고 하드웨어 키보드가 숨김 상태가 아니면) FoldKey는 배열을 띄우지 않고 오른쪽 아래에 작은 칩만 보여 준다(0.11.0). 칩에는 FoldKey의 한글·영문 상태(`한`/`EN`), 터미널에서 조합 중인 음절, ⌨ 표시가 있다. 칩 밖은 앱이 터치를 받고, 앱 화면은 줄어들지 않는다.

- 칩을 누르면 화면 키보드가 나온다(`띄우기`를 켜 두었으면 띄운 키보드). 상단 줄 `숨김`은 키보드 창을 닫지 않고 칩으로 돌아간다. 뒤로 가기로 키보드 창을 닫으면 다음에는 다시 칩부터 나온다. 키보드 연결이 끊기면 칩 대신 화면 키보드가 나온다.
- Android는 하드웨어 키보드가 있으면 앱이 명시적으로 요청하지 않은 키보드 표시를 거절하고, 시스템 설정의 화면 키보드 표시가 꺼져 있으면 키보드 창을 띄우지 않는다. FoldKey는 칩을 보이려고 이 두 판단(`onShowInputRequested`, `onEvaluateInputViewShown`)을 하드웨어 키보드가 있을 때 허용한다.
- 물리 키 입력은 앱보다 IME가 먼저 받는다. 한글 모드에서 Ctrl·Alt·Meta·Fn 없이 누른 A–Z 키는 두벌식 자모가 되고, 화면 키보드와 같은 조합기로 조합된다. 자모는 키의 물리 위치(keycode)로 정하므로 Android의 물리 키보드 배치 설정과 상관없다. Shift는 쌍자음과 ㅒ·ㅖ를 만들고, Caps Lock은 자모에 영향을 주지 않는다.
- 조합 중 Backspace는 자모 단위로 지운다. 그 밖의 키(Ctrl·Alt 조합, 방향키, 숫자·기호, 스페이스, Enter 등)는 조합 중인 음절을 확정한 뒤 앱에 그대로 넘긴다. 터미널에서는 음절을 먼저 보내고 그 키를 FoldKey가 다시 보낸다(글자는 글자로, 수정키 없는 Enter·Tab은 `\n`·`\t`로, 나머지는 키 이벤트로). 앱이 음절보다 키를 먼저 받지 않게 하려는 것이다. 뒤로 가기와 볼륨 키는 음절만 보내고 시스템에 넘긴다.
- 누르고 있어 반복되는 키는 처음 누름과 같은 방식으로 처리한다. 한글 모드에서 처음 자모로 받은 키는 반복도 자모로 들어가고, 처음에 앱으로 넘긴 키는 반복도 앱으로 간다. 조합 중에 누르기 시작한 Backspace는 음절을 다 지운 뒤 앞 글자를 지우는 키 이벤트로 이어진다.
- 한글·영문 전환:
  - 한/영 키. 한국어 키보드의 한/영 키는 HID(Human Interface Device) 사용 코드 LANG1(0x90)을 보내고, Linux는 이를 `KEY_HANGEUL`(122)로, Android의 기본 키 배치 파일(`Generic.kl`)은 `KEYCODE_KANA`로 바꾼다. FoldKey는 `KEYCODE_KANA`를 전환 키로 받는다.
  - 오른쪽 Alt만 눌렀다 떼기. 한/영이 오른쪽 Alt 자리에 있는 키보드(Windows 한국어 키보드 종류 1과 같은 배치)를 위한 것이다. 다른 키와 함께 누르면 전환하지 않고, 오른쪽 Alt 이벤트 자체는 앱에도 그대로 간다.
  - `KEYCODE_LANGUAGE_SWITCH`도 전환으로 받지만, AOSP의 창 정책(`PhoneWindowManager`)은 이 키를 앱과 IME에 보내기 전에 가져가 전환 동작에 쓴다(Android 11 소스는 물리 키보드 배치 전환, Android 16 소스는 입력 방법 전환). 이 키를 보내는 키보드나 기기에서는 FoldKey의 전환이 일어나지 않는다.
  - 한자 키(`KEYCODE_EISU`)는 처리하지 않는다. Shift+Space도 전환 키로 쓰지 않는다.
- 한글 모드에서 Esc나 Ctrl+[를 누르면 영문 모드로 바뀐다(설정의 "Esc를 누르면 한글에서 영문으로 전환").
- 원격 데스크톱 앱(설정의 "원격 데스크톱 앱", 기본 `tv.parsec.client`)에서는 물리 키를 하나도 바꾸지 않고 앱에 넘긴다. 한/영 키와 오른쪽 Alt도 FoldKey가 쓰지 않으므로 원격 PC의 한국어 입력기가 한·영을 바꾼다. 칩에는 ⌨만 보인다.
- 입력창이 없는 화면(앱 목록, 게임 등)에서는 물리 키를 처리하지 않는다. 터미널(`TYPE_NULL`)은 화면 키보드와 같이 영문으로 시작한다.

## 오타를 줄이는 장치

- 키 판정은 손가락이 닿은 순간의 좌표로 하고, 입력 확정은 뗄 때 한다. 두 엄지가 겹쳐 눌러도 누른 순서대로 입력된다. 상단 줄 버튼과 가운데 클립도 그보다 먼저 누르고 있던 키를 입력한 뒤 동작한다. ⌫는 누르는 순간 지운다.
- 시스템이 손바닥이나 쥔 손가락으로 보고 취소한 터치(`FLAG_CANCELED`, `ACTION_CANCEL`)와 다른 입력창으로 옮겨 가며 끊긴 터치는 입력하지 않고 수정키도 켜지 않는다. 누르는 순간 지운 ⌫는 되돌리지 못한다.
- 사용자의 체계적인 터치 편차를 화면에 보이지 않게 학습해서 판정 위치를 보정한다. 모든 키의 중심부(가로·세로 ±25%)는 보정과 관계없이 그 키다. 보정이 보이는 키를 누른 터치를 가운데 복제 키로 옮기지는 않는다. backspace 직후나 1초 넘게 쉬었다가 누른 키에는 보정을 쓰지 않고, 최근 8번 안에서 ⌫로 지운 입력은 학습하지 않는다. 설정에서 끄거나 초기화하고, 초기화는 실행 중인 키보드에도 바로 반영된다. 0.4.0에서 분할 배열의 키 위치가 바뀌어 분할 배열의 학습값은 처음부터 다시 쌓는다.
- 타이핑 보정(0.9.0)은 노린 키를 알고 친 탭으로 구역별 보정값을 처음부터 채운다. 보정 단계의 탭은 그 엄지의 표본 수만큼(최대 20개) 학습값의 무게를 갖고 저장되며, 그 뒤 실제 입력으로 계속 바뀐다([반쪽 높이와 크기](#반쪽-높이와-크기)).
- 설정의 "학습한 터치 편차 보기"(0.8.0)는 학습값이 저장된 배열(분할·전체·커버, 레이어, 키보드 폭)마다 키보드를 그리고, 줄과 화면 4등분 구역마다 판정에 실제로 쓰는 보정량을 화살표(4배 확대)로, 학습 표본 수를 숫자로 보여 준다. 전체 표본 수와 키 가운데에서 벗어난 평균 편차도 적는다. 화살표는 그 구역에서 키 중심보다 평균적으로 어느 쪽을 눌렀는지 가리키고, 판정할 때는 터치 위치를 그 반대 방향으로 옮긴다. 키보드 그림은 지금 설정으로 그린다.
- 설정의 "터치 히트맵과 배치 제안"(0.10.0)은 키를 누른 자리를 키마다 모아 그린다.
  - 모으는 값은 키마다 탭 수와 키 가운데에서 벗어난 거리의 합·제곱합·곱의 합뿐이다. 누른 순서나 시각은 남기지 않으므로 친 글을 되살릴 수 없다. 비밀번호 입력창의 탭은 모으지 않는다. 그 키의 칸(키 폭 × 행 높이) 바깥에 떨어진 탭과 ⌫로 지운 입력은 뺀다. 학습한 터치 편차를 꺼도 모은다.
  - 배열(분할·전체·커버, 레이어, 키보드 폭)마다 따로 모으고, 키 너비·옆 거리·올림 높이·행 높이 설정이 바뀌면 그 배열의 히트맵을 새로 시작한다. 키 위치가 바뀐 뒤에는 키 가운데에서 잰 거리가 다른 뜻이 되기 때문이다.
  - 그림은 키마다 탭의 평균과 공분산으로 만든 2차원 정규분포를 탭 수만큼 더한 밀도다(탭이 적으면 표준편차 1.2 mm 쪽으로 당긴다). 한 색의 밝기 단계로 칠하고, 밝은 테마에서는 많이 누른 곳이 진하고 어두운 테마에서는 밝다. 키 가운데에는 + 표시를 그려 색이 몰린 쪽이 어긋난 방향을 보여 준다.
  - 분할 배열에서는 엄지마다(왼쪽·오른쪽 반쪽의 글자 키) 탭 가중 평균 어긋남으로 반쪽을 옮길 자리를 제안한다. 엄지마다 탭이 150번 이상 있어야 하고, 평균이 0.3 mm 이상이면서 표준오차의 2배보다 클 때만 옮긴다(0.1 mm 단위). 가로는 그 레이어의 왼쪽·오른쪽 옆 거리를, 세로는 두 엄지를 합친 평균으로 두 레이어가 함께 쓰는 올림 높이를 바꾼다. 화면 끝(0.5 mm)이나 설정 범위에 닿으면 거기서 멈춘다.
  - "제안대로 옮기기"는 설정을 바꾸고, 두 레이어의 분할 학습값(같은 키보드 폭)을 구역마다 그 구역 키가 실제로 움직인 만큼 옮긴 뒤 히트맵을 지운다. 키가 탭 쪽으로 간 만큼 학습한 보정을 빼야 같은 자리를 두 번 보정하지 않는다. 실행 중인 키보드도 바로 새 값을 읽는다.
- 자동 수정과 단어 예측은 없다. 명령어와 식별자는 사전 단어가 아니기 때문이다.
- 햅틱은 누르는 순간 시스템 키보드 진동(`KEYBOARD_TAP`)으로 낸다. 설정에서 "틱"이나 "클릭"을 고르면 진동 효과를 직접 재생한다. 상단 줄 버튼과 가운데 클립도 같은 설정을 따른다.

레이어, 한글 조합 표시를 확인한다. `TypingCalibrationTest`는 구역마다 탭이 몇 개뿐일 때도 흩어짐을 작게 잡지 않는지 300번 반복해 평균으로 확인한다. `OffsetMapActivityTest`는 저장된 학습값으로 터치 편차 화면을 그려 `offset_map.png`를 만든다. `HeatmapActivityTest`는 정해진 탭 키보드 뷰에서 상단 줄 `일반`/`코드` 버튼으로 레이어를 바꾸고 일반 레이어에서 한글과 문장 부호, 윗줄 아래로 밀기 기호를 쳐 보며, 일반 레이어의 옆 끝 거리 설정이 일반 레이어 반쪽만 옮기는지, 측정으로 정한 값(키 4.3 mm·6.1 mm, 거리 13.7 mm·17.4 mm)이 두 레이어에 그대로 그려지는지, 0.7.1에서 정한 일반 레이어 거리가 왼쪽·오른쪽 거리로 이어지는지 확인한다. `RenderTest`는 일반 레이어도 `general_*.png`로 그린다. `ModifierTouchTest`는 실제 시간 간격을 둔 터치로 수정키 roll과 조합, 취소된 터치, Alt 전환, 고정한 Shift의 숫자 행, `한/A` 길게 누르기를 확인하고, `OutputOrderTest`는 겹쳐 누른 Enter·Tab과 글자가 터미널에 도착하는 순서를, `ServiceInputTest`는 입력 다시 시작, 화면 회전, 잠금 화면, 늦게 온 커서 위치 보고를 확인한다. `HardwareKeysTest`는 물리 키의 두벌식 조합, 한/영 키와 오른쪽 Alt 전환, 누르고 있을 때의 반복, 터미널에서 음절과 키의 순서, 원격 앱 통과를 확인한다(0.11.0). `PhysicalKeyboardTest`는 서비스에 `KeyEvent`를 넣어 입력창에 한글이 들어가는지, 칩·`숨김`·키보드 연결과 해제, 창이 늦게 열려도 터미널의 조합 중 음절이 남는지, 띄운 키보드와 접은 키보드의 insets와 터치 영역을 확인한다. `HoverTest`는 키보드 뷰의 `띄우기`·`고정`, 불투명도 슬라이더(끄는 동안과 뗀 뒤, 취소된 터치), `접기`와 손잡이, 칩의 크기와 내용을, `OverlayTest`는 표시 상태 규칙을 확인한다. Robolectric의 `KeyCharacterMap`은 Ctrl+A에도 글자 `a`를 돌려주는 등 실제 Android와 달라서, 일반 입력창의 Ctrl 단축키는 에뮬레이터나 기기에서 확인해야 한다. 기기에서 확인할 항목은 [docs/research.md의 10.3절](docs/research.md#103-기기에서-확인할-항목)에 있다.

## 알려진 한계

- 폴드7 실기기에서 시험하지 않았다. Android 11 에뮬레이터(폴드7 내부 화면 해상도와 밀도)에서 키 이벤트, 한글 조합, Ctrl 단축키, 가로 분할 배열을 확인했다. 햅틱 느낌, One UI(삼성 user interface)의 키보드 진동 설정 연동, `xdpi` 정확도, 작업 표시줄과의 상호작용, Android 16의 하단 insets 처리는 기기 확인이 필요하다.
- 접근성 서비스(TalkBack)용 가상 뷰 구조를 제공하지 않는다.
- 물리 키보드 처리는 Android 11 에뮬레이터에 `hid` 명령으로 등록한 가상 블루투스 키보드로 확인했다. 폴드7과 실제 블루투스 키보드에서 한/영 키가 `KEYCODE_KANA`로 오는지, One UI가 이 키를 먼저 가져가지 않는지는 확인하지 않았다.
- 띄운 키보드의 터치 통과, insets, 불투명도는 Android 11 에뮬레이터(3버튼 내비게이션)에서 확인했다. 제스처 내비게이션에서 키보드 영역의 뒤로 가기 제스처가 막히는지, Android 16에서 IME가 직접 그리는 내비게이션 버튼과 어떻게 겹치는지, Parsec에서의 동작은 확인하지 않았다.
- Esc, 방향키, Ctrl 조합처럼 키 이벤트로 보내는 키는 같은 순간에 보낸 글자보다 늦게 도착할 수 있다. 터미널의 Enter·Tab과 여러 줄 입력창의 Enter는 글자로 보내 이 경우를 피했고, ⌫는 누르는 순간 보내 앞뒤 키와 한 번에 나가지 않게 했다. 물리 키보드로 터미널에서 한글을 치다가 이런 키를 누를 때도 같다. 조합 중인 음절은 그 키보다 먼저 도착하지만, 앱의 메인 스레드가 밀려 있으면 그 뒤에 이어 친 음절이 키를 앞지를 수 있다(에뮬레이터에서 0.12초 간격으로 쳤을 때 일어났고, 3초를 쉬었을 때는 두 번 모두 순서대로 도착했다).
- 수정키를 빠르게 이어 친 것(roll)과 조합을 가르는 0.15초는 사람 대상으로 재서 정한 값이 아니다.
- 한자 변환은 없다. 사전 데이터가 필요해서 넣지 않았다.
- `한/A` 길게 누르기가 원격 PC의 한글·영문을 바꾸는지는 원격 앱이 Android의 오른쪽 Alt 키 이벤트를 원격 PC에 그대로 넘기는지와 원격 PC의 한국어 키보드 종류에 달려 있다. 같은 이벤트를 보내던 이전 키보드 앱이 Parsec에서 동작했다는 사용자 보고가 있고, FoldKey 0.10.0을 Parsec에서 직접 시험하지는 않았다. Robolectric에서는 앱이 받은 이벤트가 오른쪽 Alt의 누름·뗌 두 개이고 meta와 flags가 0인 것까지 확인했다.
